# Lab 5 final deliverables

Files included: `library_system.py`, `issues.md`, `reflection.md`, the three original reports, and a script to generate the final reports locally.

## Generate final reports on Windows PowerShell

Activate the virtual environment and run:

```powershell
python -m pylint library_system.py > pylint_after.txt
bandit -r library_system.py -f txt -o bandit_after.txt
flake8 library_system.py > flake8_after.txt
```

Review the reports before submitting. These reports are generated by the installed versions of your tools, so they should be produced on your own machine rather than fabricated in advance.

## Three-commit sequence

After copying the final `library_system.py`, `issues.md`, and `reflection.md` into your local repository, use the following sequence. This creates three local commits that group the work by tool focus. Review `git status` before each commit.

1. `git add library_system.py; git commit -m "Fix Bandit security findings"`
2. `git add library_system.py; git commit -m "Fix Pylint code quality issues"`
3. `git add library_system.py issues.md reflection.md pylint_before.txt bandit_before.txt flake8_before.txt pylint_after.txt bandit_after.txt flake8_after.txt; git commit -m "Fix Flake8 style and add lab reports"`

Important: Git does not allow a single file's final state to be meaningfully split across earlier commits unless you stage selected hunks or make the changes in stages. The commands above are a simple grouping template, but because `library_system.py` is already at its final state, the first commit will include all its final changes. For three genuinely distinct code-fix commits, make each change group and commit it before applying the next group. Push only if your repository permissions allow it.
